# Demo mode: try SquadLogic on a ready-made league

Kind: feature · Drawn up: 2026-10-22 against `origin/main` at `0e9fd31` · Owner: the repository owner
· Status: **proposed, for owner approval** (AGENTS.md rule 14: persistence, authentication and
authorization, the scheduler; a new environment variable).

Every claim about the code is _statically reviewed_ (read) unless marked _executed_. The demo
league is `fixtures/demo-2026/` from PR #637, which this plan builds on.

## Why

A league administrator deciding whether SquadLogic fits their league can't judge it from an empty
account: the value is in what it does with a season's registrations. The demo hands them a full
recreational league (128 teams, 1,259 players, 251 coaches, all placeholders) to generate teams and
schedules with, for an hour, without an account and without their own data. The same league is a
realistic seed for the real-backend tests and for staging.

There is no `docs/product.md`; AGENTS.md sections 1-2 (the mission, the hard exclusions, the
privacy rules) stand in for it, as for the phase plans. A public demo is not a "public club site"
(section 2.1): it shows the product, not a league's own pages.

## Behavior

- **Now:** a visitor without an account sees the sign-in page and can sign up and create an
  organization (`Login.jsx:289-308`, `initialize_new_tenant`), which starts empty.
- **After:**
  - The sign-in page offers **Try the demo** on a deployment that enables it.
  - One click gives the visitor a private copy of the demo league, with them as its
    administrator, without an email address:
    - the season;
    - divisions grouped into programs, with teams and rosters;
    - coaches assigned;
    - fields and practice slots.
  - A banner says it is a demo and how long is left. Five minutes before the hour it warns. At the
    hour the visitor is signed out to a "your demo has ended" page with **Start again** and
    **Create an account**.
  - The copy is deleted within ten minutes of expiry.
  - Trying to import a file opens a notice instead of the file picker. It offers to create an
    account on this deployment, or to run SquadLogic yourself, and names the official hosted
    service only on a deployment configured to.
  - U4 has four practice cohorts with one 30-minute session a week each, one at a time, at least
    15 minutes apart, and no games.
- **Unchanged:**
  - Sign-up, organization creation and invites for real accounts.
  - Every RLS policy and RPC as a real member sees them.
  - The production build never falls back to the mock client (`tests/mockModeGuard.test.js` stays
    green, unedited).
  - A deployment that does not enable the demo shows nothing of it.

## Out of scope

- A client-only demo on the mock client (weighed below and not recommended).
- Converting a demo into a real account; the data is placeholders, and "Create an account" starts
  empty.
- Previewing the demo as a coach or a guardian (decision 4).
- Mapping `Payment Plan` to programs and divisions at import; that is Phase E's import mapping. D1
  only stops the column being thrown away.

## Options

**A. Client-only demo on the mock client.** It needs no backend and costs nothing to run, but it
would show a different product:

- The scheduler, team generation and every save are Edge Functions the mock does not run. In a
  deployed build they go to localhost, which the CSP blocks.
- The mock would have to ship in production behind a new build flag, with the seven
  build-guarded RPC groups and the eight `IS_MOCK_MODE` constants turned into runtime state.
- It re-merges the whole store on every read, which won't carry 1,500 people.
- It would share `localStorage` (the auth token, `squadlogic_active_org`) with a real session on
  the same origin.
- Every RPC the product adds would need a mock twin before the demo shows it.

**B. A server-side demo organization (recommended).** The real product on the real backend:

- The visitor signs in anonymously.
- One RPC copies the demo league into a new organization marked with its expiry.
- A `pg_cron` job deletes expired copies.
- RLS, the RPCs, the Edge Functions and the audit trail work unchanged, because a demo
  organization is an organization.

The costs:

- Anonymous sign-in must be enabled on the hosted project, and anonymous users must be fenced out
  of everything real (decision 1).
- Each live demo takes about 4-6 MB, so concurrent demos are capped (decision 2).
- Abuse is bounded by Supabase's per-IP limit, the cap, and optionally CAPTCHA (decision 3).

## Design

### D1. Import fixes the fixture exposed (small; real users benefit first)

A prospective league's GotSport export has the same shape as the fixture, so these are fixed before
the demo invites them to make an account and import.

- **Coaches get a full name** when the export has only first and last name. The server composes
  `full_name` from `first_name` + `last_name` when it is absent, in `import-validation` before
  `validateRow`. The frontend `REQUIRED_HEADERS.coaches` accepts the pair, and the ColumnMapper's
  composition stays for other shapes.
- **A duplicated canonical key keeps the first non-blank value**, not the last value. This applies
  in `import-validation` and in ImportPanel's `buildPreview`, matching the ColumnMapper, which
  already keeps the first.
- **`Payment Plan` is kept.** It is a registration product name, not a payment. It moves to
  `ALLOWED_HEADERS` in both copies (`sensitiveHeaderParity` keeps them equal) and is stored as
  `registration_plan`, read by nothing until Phase E maps it.
- **Not changed:** every other sensitive pattern, including `payment status` (already allowed)
  and real financial columns (`/card/`, `/billing/`).
- **Tests:**
  - `tests/demoFixture.test.js`: the coach header check expects `[]`, the email-loss count
    expects 0, and a new case requires `Payment Plan` to survive the filter.
  - `tests/sensitiveHeaderParity.test.js` and a Deno mirror test of the composition.
  - `tests/importHeaders.test.js`: first/last satisfies coaches, and a missing last name still
    fails.

### D2. Practice-only divisions and reserved practice slots (medium; solver, schema)

- **Schema:**
  - `divisions.plays_games boolean NOT NULL DEFAULT true`.
  - `practice_slots.division_id uuid NULL`, a foreign key to `divisions` in the same organization
    (composite, as Phase E's `programs` does).
  - A slot with a division is used only by that division's teams. A division with reserved slots
    uses only those.
- **Writers:** `admin_upsert_division_settings` takes `plays_games`, and the practice-slot writer
  takes `division_id`. Both are audited as they are today.
- **Games:** `buildRoundRobinByDivision` skips `plays_games = false` divisions, and the page shows
  them as "practice only", not as unscheduled.
- **Practices:**
  - Core `schedulePractices` and the Edge solver honour slot reservation.
  - The slot writer refuses a slot that overlaps another on the same field, or starts less than the
    field's turnover (default 15 minutes) after one ends. That is the first live enforcement of the
    turnover rule, at the point of writing.
- `rosterSizing` no longer throws on a non-"NvN" format (the division's own roster limits apply).
- **Tests:**
  - `packages/core` unit tests: a `plays_games = false` division gets no fixtures and is not
    counted unscheduled; reserved slots go only to their division; four U4 cohorts in four
    reserved 30-minute slots 45 minutes apart each get one; a fifth slot at 25 minutes is refused.
  - pgTAP `practice_only_divisions.sql`.
  - The season-2026 fixture suite stays green (AGENTS.md, scheduling conventions).

### D3. The demo organization (medium-large; migrations, RPCs, cron)

- **Data:**
  - `organizations.demo_expires_at timestamptz NULL` (set means demo).
  - A `demo_seed` schema, not exposed to PostgREST, whose tables hold the league as the fixture
    shapes it: season, programs, divisions, teams, players, guardians, coaches, assignments,
    fields, practice slots including the four U4 sessions.
- **Seed generation:**
  - Its insert migration is generated from `fixtures/demo-2026/*.csv` by
    `scripts/build-demo-seed.mjs`.
  - A Vitest drift test regenerates it and compares, so the seed and the fixture cannot diverge
    and nobody hand-edits the SQL.
- **`start_demo_session()`** (SECURITY DEFINER):
  - **Refuses:**
    - a caller who is not anonymous (`auth.jwt()->>'is_anonymous'`);
    - a caller who already has a live demo (it returns that one instead);
    - when the number of live demos is at the cap (decision 2), with a clear "try again in a few
      minutes".
  - **Creates**, in one transaction:
    - the organization, named "Demo league", expiring an hour later;
    - the caller as its admin;
    - a copy of every `demo_seed` table with fresh ids;
    - one `demo.started` audit row.
  - **Returns** the organization id and expiry.
- **Fencing anonymous users** (each a refusal with a test):
  - `initialize_new_tenant`, `create_org_invite` and `redeem_org_invite` refuse anonymous callers.
  - Every import path refuses a demo organization: `create_import_job`, the finalize RPCs, and
    `import-validation` (`organization_id` is a demo).
  - The `exports` bucket's insert policy refuses a demo organization's folder. A storage delete
    from SQL leaves the bytes behind, so no object may be created that a purge would have to
    clean.
  - The pgTAP enumerates every RPC granted to `authenticated` and requires each to be on an
    "allowed for anonymous" list or to refuse anonymous callers. The universe comes from the
    catalogue, not from this plan.
- **`purge_expired_demos()`** (definer, not granted to any client role):
  - Deletes expired demo organizations, and with them every org-scoped row.
  - Deletes the anonymous `auth.users` with no remaining membership.
  - Records the counts in `demo_purge_log`.
  - `pg_cron` runs it every 10 minutes.
  - The pgTAP seeds a demo, expires it and purges it. It then requires no row in any table with an
    `organization_id` column (enumerated from `information_schema`) to name it, and no `auth.users`
    row for its user.
- **Rollback:** revert and smoke scripts under `docs/sql/` as for every migration. The revert
  drops the cron job first.

### D4. The demo in the app (medium; UI, env)

- **Environment** (through `env.js`, `envRules.js`, `.env.example` and `ENVIRONMENT.md`, held by
  `tests/env.test.js`):
  - `VITE_DEMO_ENABLED`: `true` shows the entry point. It is unset on a self-hosted deployment,
    whose backend may not allow anonymous sign-in.
  - `VITE_OFFICIAL_SITE_URL`: an optional http(s) URL, set only on the official deployment's
    Vercel project. When it is set and is not the current origin, the import notice can say
    "SquadLogic is also hosted at …".
  - The official domain appears in no source file. A test greps `frontend/src` for it, and the
    one existing source mention (`env.js:59`, a comment naming `squadlogic.vercel.app`) is rewritten
    in the same PR.
- **Entry:** a **Try the demo** button on the sign-in page calls `signInAnonymously()` and then
  `start_demo_session()`, then opens the dashboard on the demo organization. Errors are announced,
  never swallowed: the cap is reached, or anonymous sign-in is disabled.
- **Banner:** a persistent banner in the top bar with role `status`:
  - It reads "Demo league: resets in 42 min", and offers **Leave demo**.
  - At five minutes an `aria-live="polite"` warning appears.
  - At expiry the app signs out and routes to `/demo/ended`, with **Start again** and **Create an
    account**.
  - It uses the existing tokens in both themes, is keyboard-operable, and passes axe.
- **Import intercept:**
  - In a demo organization, `validateAndReadFile` and the drop zone open a dialog, with focus
    trapped and restored on close.
  - The dialog says the demo holds placeholder data only. It offers **Create an account here**
    (signs out of the demo and opens sign-up) and **Run your own SquadLogic** (the self-hosting
    guide, decision 5). With `VITE_OFFICIAL_SITE_URL` set, it adds the hosted-service line.
  - Export uploads are hidden in a demo; downloads still work.
- **Sentry:** `logger.setUser` adds `demo: true` for a demo organization, so demo errors can be
  filtered and never count as a real league's.
- **Bundle:** the banner and the intercept are small. `/demo/ended` and the dialog are lazy. The
  main entry must stay under its cap: `npm run check:bundle`, and the bundle-budget doc's table
  is refreshed.
- **Mock mode** (for the mock E2E suite only): the mock gains `signInAnonymously` and a
  `start_demo_session` that seeds a small slice of the fixture (two divisions), enough for the UI
  tests. Its size keeps the mock's per-read cost tolerable.
- **Tests:**
  - `tests/demoEntry.test.jsx`: the button appears only with the flag; errors are announced.
  - `tests/demoBanner.test.jsx`: countdown, warning, and expiry routing with fake timers.
  - `tests/demoImportIntercept.test.jsx`: no file is read, and both links are present; the hosted
    line appears only with the env var, and never on the official origin itself.
  - `tests/env.test.js`: the two new names.
  - An E2E feature `demo_mode.feature` on the mock.
  - A real-backend scenario `real_backend_demo.feature`: start, see 128 teams, generate practices
    with U4 in its four sessions and no U4 games, import refused, purge removes it.

## Risks and rollback

- **Risk:** an anonymous user reaches something real.
  - **Watch:** the D3 pgTAP catalogue check fails on any new client-callable RPC that does not
    decide.
  - **If it happens:** the RPC refuses anonymous callers before release.
- **Risk:** the purge stops running and demos pile up toward the 500 MB threshold.
  - **Watch:** `demo_purge_log` has no row in the last 30 minutes, and the count of expired demo
    organizations is above zero. Both are checked by the existing advisors gate's companion query,
    and visible to the owner.
  - **If it happens:** run the purge by hand through a migration-free admin RPC, and fix the job.
- **Risk:** a burst of demos hits the cap.
  - **Watch:** the RPC's refusals are logged with a count.
  - **If it happens:** raise the cap if there's room, or add CAPTCHA.
- **Risk:** the seed drifts from the fixture.
  - **Watch:** the drift test.
  - **If it happens:** regenerate.
- **Rollback:**
  - Set `VITE_DEMO_ENABLED` unset: the entry point disappears with no deploy of data.
  - Disable anonymous sign-in.
  - Revert D3 with its script, which drops the cron job, deletes demo organizations and drops
    `demo_seed`.
  - D1 and D2 revert independently.

## Decisions for you

1. **(blocking) Server-side demo (B) over client-only (A)**, with anonymous sign-in enabled on the
   hosted project. _Recommended: B._ A would demo a product without its scheduler, and it costs a
   permanent mock twin of every feature.
2. **How many demos at once.** _Recommended: 25 live demos_ (about 100-150 MB at the estimate,
   under a third of the free threshold). D3 measures the real footprint before launch.
3. **CAPTCHA (Cloudflare Turnstile) on anonymous sign-in**, as Supabase recommends for anonymous
   users. _Recommended: yes at launch._ It is a hosted-project setting plus a widget on the demo
   button, and the 30-an-hour per-IP limit alone doesn't stop a distributed burst.
4. **Coach and guardian preview in the demo.** _Recommended: not in the first version._ Preview
   swaps only the displayed profile, so it would not show what a coach really sees. That needs
   real member accounts per demo, which anonymous sign-in gives only one of.
5. **The self-hosting link.** Is the repository public, so "Run your own SquadLogic" can link to
   its guide? _Recommended:_ link to the guide in the repository if it is public. If not, offer
   only "Create an account here", and add the self-hosting option when it is public.
6. **Order against Phases B-E.** _Recommended:_ D1 next (it fixes real GotSport imports and is
   small), then Phase B, with D2 alongside Phase D (both scheduling) and D3-D5 after B. Or say if
   the demo should come first, to show prospects sooner.

- Not run: the per-demo footprint (estimated from production `coaches`; production `players` is

  (`index.ts:56` vs `:88`), and whether organization deletion cascades to every org-scoped table

- `production-cutover.md` is marked historical and names the project ref. The self-hosting guide
  replaces it as the current setup reference.
- The fixture's Minis gap in season-2026 is 20 minutes. The demo uses the owner's 15 as its slot
  spacing, and the turnover default in D2 is 15.
